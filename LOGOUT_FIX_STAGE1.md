# Исправление выхода из аккаунта (этап 1.1)

## Причина

В предыдущем патче `frontend/src/config.js` значение `API_URL` было изменено на пустую строку. Это правильно для вызовов, написанных как `${API_URL}/api/...`, но Axios-клиент `$api` использовал `baseURL: API_URL` и относительные адреса `api/auth/login` и `api/auth/logout`. При нахождении пользователя на `/autmama/` браузер мог отправлять эти запросы на `/autmama/api/auth/logout` вместо `/api/auth/logout`. Nginx трактовал такой адрес как React-маршрут, и запрос не доходил до backend.

## Что исправлено

- `frontend/src/http/index.js`: `baseURL` теперь `${API_URL}/`, то есть `/` для текущей конфигурации. Все вызовы `$api` с относительным путём `api/...` идут на `/api/...`.
- `bff/controllers/userController.js`: удалён вывод refresh-токена в журнал при обновлении сессии.

## Как проверить

1. Сохранить старый проект и его данные; не использовать `docker compose down -v`.
2. Из каталога исправленной версии: `docker compose up -d --build` (при занятом порту сначала остановить старые контейнеры командой `docker compose down` из их каталога).
3. Войти в аккаунт, затем нажать «Выход».
4. В инструментах разработчика браузера (F12 → Network) должен появиться `POST /api/auth/logout` со статусом 200. Не должно быть `POST /autmama/api/auth/logout`.
5. После выхода ссылка «Войти» должна отобразиться, а локальный ключ `token` должен исчезнуть.

Если ошибка сохранилась, пришлите статус и тело ответа `POST /api/auth/logout`, а также `docker compose logs --tail=50 bff` (не присылайте сами токены/куки).

Это исправление адресации; оно не является полноценным аудитом безопасности и пока не предназначено для публичной эксплуатации с данными детей.
