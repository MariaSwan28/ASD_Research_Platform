# Этап 16 — роли и назначение специалистов

Историческое описание версии 16. В текущей версии 16.1 административное создание ограничено специалистами, регистрация родителей открывается настройкой ALLOW_REGISTRATION, добавлены ФИО. Актуальная инструкция — `STAGE16_1_NAMES_FORMS.md`.

В этой версии добавлены три роли и связь «ребёнок — специалист». Правила доступа к материалам и результатам для специалистов будут расширяться отдельным этапом.

## Возможности

| Роль | Доступ на первом этапе |
|---|---|
| Родитель | Свои профили, заметки, материалы, анализы и история. В карточке ребёнка видны назначенные специалисты. |
| Специалист | Список закреплённых детей и просмотр имени/псевдонима и даты рождения. Без редактирования, заметок, материалов и анализов. |
| Администратор | Создание родителей и специалистов, список пользователей, смена ролей родитель/специалист, назначение и снятие специалистов. Для назначения доступны имя ребёнка и почта владельца; родительские заметки и чужие материалы не открываются. Свои прежние материалы доступны по ссылке «Мои материалы». |

Назначения делает только администратор. У ребёнка может быть несколько специалистов, у специалиста — несколько детей. Родитель не может назначить специалиста самостоятельно. Самостоятельная регистрация создаёт только родителя. Дополнительные роли нельзя запросить в форме регистрации или получить подстановкой роли в запрос/JWT.

## Обновление существующей установки

1. Перед обновлением создайте резервную копию: `python scripts/backup.py` (требуются Python и Docker). Для сервера используйте `python3 scripts/backup.py --compose compose.timeweb.yml`.
2. Распакуйте полный архив в отдельную папку, затем перенесите исходники в существующую папку проекта. Сохраните свой `.env`. Не удаляйте Docker volumes и не используйте `down -v`.
3. Проверьте `SUPERUSER_LOGIN` в существующем `.env`: именно эта учётная запись получит роль администратора. `SUPREUSER_PASS` задаёт пароль при создании нового аккаунта; пароль уже существующего аккаунта обычно сохраняется. Исключение прежней версии — ротация известного стандартного пароля `admin@mail.ru`.
4. Выполните из корня проекта:

```bat
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

5. Откройте `http://localhost:3000/autmama/`, обновите страницу Ctrl+F5 и заново войдите.

Для Timeweb в командах Compose используйте `--env-file .env -f compose.timeweb.yml`.

Миграция выполняется автоматически при запуске BFF: добавляет роль к пользователям и таблицу назначений. Существующие пользователи становятся родителями, аккаунт `SUPERUSER_LOGIN` — администратором. База, владельцы профилей, файлы, результаты и пароли не пересоздаются. Не запускайте прежнюю версию поверх базы после обновления без проверки совместимости; для отката восстановите резервную копию.

## Как проверить

1. Войдите под `SUPERUSER_LOGIN` — откроется кабинет администратора.
2. Создайте пользователя с ролью «Родитель» и пользователя с ролью «Специалист». Укажите их почту и пароль (8–32 символа). Администратор передаёт данные входа пользователям самостоятельно; автоматическая рассылка не добавлена. На сервере с закрытой регистрацией родителя также создаёт администратор.
3. В отдельном браузере или приватном окне войдите родителем, создайте профиль ребёнка и при необходимости загрузите материалы.
4. В кабинете администратора обновите список профилей, выберите специалиста и нажмите «Назначить».
5. Войдите специалистом. Откройте карточку ребёнка: доступны только имя/псевдоним и дата рождения. Профили другого родителя без назначения, заметки, файлы и анализы не должны открываться.
6. Снимите назначение администратором. Обновите кабинет специалиста — профиль исчезнет. Сервер запрещает последующие запросы сразу после снятия назначения, даже со старым токеном; уже отображённые данные браузера исчезают после обновления.
7. Перезапустите контейнеры и проверьте сохранение ролей, профилей и действующих назначений.

Можно изменить роль существующего пользователя, но переход родителя в специалиста запрещён, пока у него есть профили или материалы: для такого случая создайте отдельную учётную запись. Перед сменой специалиста на родителя нужно снять его назначения. Роль администратора через этот интерфейс не выдаётся и не снимается.

## Технические изменения

- `Users.role`: `parent`, `specialist`, `admin`; `ChildSpecialists`: пары ребёнок/специалист, кто назначил и даты.
- `services/roleMigration.js`: добавляющая миграция без `sync({alter:true})` или пересоздания данных.
- `middleware/auth.middleware.js`: актуальная роль читается из БД при каждом защищённом запросе.
- `/api/admin/users`, `/api/admin/children` и маршруты назначений доступны только администратору. В ответах нет хешей паролей.
- `/api/children` и `/api/children/:id` для специалиста отдают только закреплённые профили и ограниченный набор полей. Изменение и удаление специалисту запрещены.
- Маршруты файлов, анализов, результатов и потокового видео не открывают доступ специалистам. Настройка собственного аватара остаётся доступна всем ролям.
- Новые кабинеты React выбираются по роли. Проверка прав на сервере не зависит от скрытия кнопок интерфейса.

## Проверки этой редакции

- 7 серверных тестов прошли. Новый интеграционный тест использует HTTP и SQLite: обновление старой схемы, сохранение данных, закрытые маршруты, подмена роли, назначение/повторное назначение, снятие доступа, смена роли с уже выданным токеном, каскадное удаление привязок.
- 17 тестов React прошли, в том числе создание специалиста, назначение/снятие, просмотр профиля специалистом и очистка отозванного профиля при обновлении.
- Production-сборка React проходит; остаются предупреждения линтера прежней версии.
- Состав сквозной проверки BFF и ограничение браузерного прогона описаны в `demo/stage16-verification.json`.
- ML-код и артефакты моделей не изменены. Docker-сборка и сервер Timeweb в этой среде не запускались; после обновления нужны проверка в Docker и резервная копия.
