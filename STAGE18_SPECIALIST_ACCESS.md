# Этап 18 — работа специалиста и краткие отчёты родителей

## Изменения

| Возможность | Родитель | Специалист |
| --- | --- | --- |
| Профили детей | Свои дети | Только назначенные администратором |
| Материалы | Свои общие материалы и материалы своих детей | Материалы назначенных детей |
| Загрузка файлов, создание рассказа, анализ | Да | Да, для назначенного ребёнка |
| Удаление материалов | Да | Да, для назначенного ребёнка |
| Результаты и история | Итог и основные показатели каждого запуска | Полные отчёты каждого запуска |
| Теги при загрузке | Нет | Только для видео |
| Создание детей | Да | Нет |
| Редактирование профиля ребёнка | Да | Да, для назначенного ребёнка |
| Удаление пустого профиля ребёнка | Да | Да, для назначенного ребёнка |

Администратор по-прежнему управляет аккаунтами, существующими профилями и назначениями. Личного пространства и создания детей у администратора нет. Самостоятельная регистрация создаёт только родителей.

Специалист видит поиск по ФИО над списком назначенных детей. Поиск работает по части имени без учёта регистра. Для работы с материалами сначала нужно выбрать ребёнка. Общие материалы родителя и материалы неназначенных детей закрыты.

Рассказ сохраняется сразу после нажатия «Сохранить рассказ», без окна тегов. Это действует для обеих ролей. При выборе нескольких файлов специалистом теги предлагаются только для видео; остальные файлы загружаются сразу. Перетаскивание файлов работает по тем же правилам.

## Хранение и отчёты

Файлы специалиста сохраняются у родителя в профиле выбранного ребёнка. Квота расходуется у родителя. История анализов общая для ребёнка: родители видят краткие результаты, назначенные специалисты — полные. Полный результат в базе не сокращается.

Сервер формирует родительский ответ по разрешённым полям, а не скрывает полученные данные только в интерфейсе. Родителю не передаются подробные таблицы, изображения, аудио, обработанное видео, ссылки на артефакты, параметры и исходный JSON. Скачивание исходного загруженного материала остаётся доступным.

Назначения проверяются при каждом запросе, включая скачивание и загрузку частями. Отмена назначения закрывает доступ и запрещает завершение активной загрузки. Учётная запись и роль проверяются по базе, а не по роли в JWT.

Старые сохранённые результаты также проходят серверное разграничение. Для старого результата без краткого заключения показывается сообщение о недоступности краткого итога; подробные данные доступны специалисту в истории. Непривязанные к конкретному запуску старые видео и JSON по совпадающему имени файла через служебные маршруты больше не выдаются: используйте сохранённый отчёт или повторите анализ.

## Обновление

Сохраните `.env`, рабочие данные и Docker volumes. Замените исходники и выполните из корня проекта:

```bat
docker compose --env-file .env up -d --build
```

Обновите страницу через Ctrl+F5. Изменение прав и краткие отчёты действуют сразу, повторный анализ обычно не нужен. Для новой формулировки заключения видео из версии 17.1 нужен новый запуск, если результат был сохранён до неё. Новых переменных окружения или миграций базы для этапа 18 нет.

## Проверка вручную

1. Под администратором создайте специалиста и назначьте ему ребёнка родителя.
2. Под родителем сохраните рассказ и загрузите видео: окно тегов не должно появиться.
3. Под специалистом найдите ребёнка по ФИО, выберите профиль, загрузите текст и видео. Окно тегов появляется только для видео.
4. Запустите анализ от обеих ролей. Родитель видит итог, основные показатели и историю. Специалист видит полный отчёт и историю обоих запусков.
5. Снимите назначение под администратором и обновите список специалиста. Доступ к материалам и отчётам должен закрыться.

## Для разработчика адаптера

`conclusion` и скалярные `metrics` — публичный итог для родителя. Таблицы деталей, изображения, аудио, видео, файлы, `parameters` и `raw_output` доступны специалисту. В публичные поля не следует помещать внутренние сведения и подробную разметку. Родительский API-ответ содержит `report_view: "brief"`; он формируется отдельно от полного результата адаптера. Исходный контракт ML и сохранённый полный отчёт формата 1.3 не изменены.

Автоматические проверки охватывают роли, чужие профили, изоляцию соседних детей одного родителя, прямую и составную загрузку, квоту владельца, теги, общий журнал запусков, выдачу краткого и полного отчётов, старую историю и отзыв доступа. Модели и их веса не изменялись. Docker и полный видеопрогон в этой среде не запускались.
