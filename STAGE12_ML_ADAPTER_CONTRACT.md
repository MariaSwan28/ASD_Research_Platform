# Этап 12 — единый контракт ML-адаптеров

Основа: приложенный `ASD_Research_Platform_stage11_auth_navigation.zip`.
Дата: 13 ноября 2026 года.

## Результат

Для общего API введён JSON-контракт 1.0: обязательные сведения о модели, материале,
запуске, статусе и времени + список частных параметров модели, артефакты, предупреждения
и структурированная ошибка. Новый адаптер подключается через Python-модуль и описание
модели; отдельные маршруты и JSX для обычной файловой модели не нужны.

Подробный контракт, назначение каждого поля, шаблон подключения, входные данные,
типы параметров и критерии проверки описаны в `docs/ML_ADAPTERS.md`.
Эта инструкция заменяет правила подключения адаптеров из `STAGE9_UNIVERSAL_ML.md`.

## Изменения

### Python

- `core/result_contract.py`: упаковка обычного результата в описанные параметры,
  проверки типов, дубликатов, таблиц, конечности чисел и JSON-сериализации.
- `core/adapter_runner.py`: общий запуск без Flask-контекста, добавление метаданных,
  единый ответ для успеха и ошибки. Неверный ответ модели — ошибка 502, не completed.
- `core/video_service.py`: видеообработка вынесена из HTTP-обработчика. Старый и общий API
  используют одну реализацию. Сохранены прогресс, блокировка параллельного видеоанализа
  в одном процессе и прежние выходные файлы. Новый экземпляр анализатора на каждый запуск
  исключает перенос статистики между видео. Результат остаётся в статусе после разблокировки.
- `movement_video.py`: адаптер использует переданный payload, а не зарегистрированный
  Flask-обработчик. Все поля исходного результата попадают в параметры.
- `parent_story.py`: прежний текстовый результат упаковывается в тот же контракт.
  Метки не получают неподтверждённой расшифровки; ограничения модели видны в warnings.
- `model_registry.py`: проверяется описание адаптера и версия контракта; ошибка проверки
  готовности не ломает остальные статусы. Ошибка импорта модуля логируется отдельно.
- `server.py`: общий API стал транспортом для runner. Тяжёлые видеоимпорты и загрузка
  моделей убраны из старта приложения; контейнерный путь лог-файла больше не нужен
  для импорта Flask-приложения. Старые видео- и текстовые ответы сохранены.

### BFF и SQLite

- Проверяются обязательная структура ответа и соответствие ID запуска, файла и модели,
  версии, модальности и операции. Чужой/неверный ответ не сохраняется как успешный.
- BFF создаёт ID запуска, передаёт доверенный контекст и серверный путь, сохраняет
  полный канонический JSON в существующую `UnifiedAnalysisResults`.
- После попытки вызова модели сохраняются и успехи, и ошибки; предварительный отказ
  доступа/совместимости/готовности не создаёт фиктивный запуск.
- При сетевой ошибке, таймауте или неверном ответе создаётся JSON ошибки по тому же контракту.
- `hasAnalysis` выставляется только для успешной операции `movement-analysis`.
- Маршрут статуса теперь требует авторизацию и не отдаёт пути/результат другого пользователя.
- Схема SQLite не изменена, новые таблицы и миграции не добавлены. Прежняя история читается.

### Интерфейс

- «Анализ» у видео открывает тот же выбор модели, что и у остальных материалов.
- Сохранено специализированное окно «Результат» для видео. После обработки доступна
  кнопка «Анализ / JSON» для общего отчёта и последующих запусков.
- Общий отчёт показывает метаданные запуска, все описанные параметры, таблицы,
  вложенные группы, предупреждения и ошибки. Неизвестный тип имеет JSON-представление.
- Длинные списки раскрываются порциями, без потери остальных элементов. Полный JSON
  можно открыть и скачать, включая ещё не раскрытые элементы.
- Ноль, false, пустая строка и null различаются; null отображается как «Нет данных».
- Историю можно переключать между запусками. Старые результаты читаются даже при
  отсутствии адаптера в текущем каталоге. API сохраняет прежний предел в 40 записей.
- Во время вызова нельзя переключить модель или закрыть окно кнопкой; прогресс видео
  показывается при наличии статуса именно этого материала.
- В режиме плиток смонтированы уже существовавшие окна просмотра видео/аналитики:
  раньше кнопки меняли состояние, но сами окна в этой ветке не отображались.
- В devDependencies закреплён `typescript: 4.9.5`: установка без frontend lock-файла
  подтягивала TypeScript 7.0.2, вызывавший сбой конфигурации ESLint React Scripts 5.
  После закрепления обычная сборка проходит без отключения ESLint.

## Проверки, выполненные в среде подготовки

| Проверка | Результат |
| --- | --- |
| Python unittest: 10 тестов | Пройдены, Python 3.12.14 + Flask 2.3.3 / Werkzeug 2.3.7 |
| Синтаксис всех Python-файлов с грамматикой Python 3.10 | Пройден |
| BFF: валидатор + HTTP/SQLite | 2 теста пройдены на Node.js 18.20.8 и 24.22.1 |
| React: параметры, JSON-скачивание, ошибки и старая история | 5 тестов пройдены |
| `npm run build` frontend с включённым ESLint | Успешно, остаются предупреждения в существующих файлах |

Python-тесты используют подменённый анализатор и подменённое текстовое предсказание:
проверены прямой вызов без Flask, совместимость старого/общего видео-API, прогресс,
параллельный отказ 409, восстановление после ошибки, неизвестные показатели, недоступные
зависимости и отклонение неверных результатов. Настоящие обученные модели не загружались.

HTTP-тест BFF использует настоящий Express, авторизацию JWT и временную SQLite,
но подменяет ML-сервис тестовым HTTP-сервером. Проверены права, доверенный контекст,
полное сохранение 65 элементов, completed/failed/409, старые записи и видеофлаг.

В React-тестах проверены типы, таблицы, будущий неизвестный тип, дополнительные элементы
списка, полнота скачиваемого JSON и история ошибок/удалённого адаптера. Это тесты DOM,
а не полный сценарий приложения в браузере.

Исходный BFF package-lock не проходит `npm ci` под npm 11 из-за несовпадений транзитивных
socks/ip-address. Для проверок использован `npm install --package-lock=false`; lock-файл
в этом этапе не изменён. BFF Dockerfile, как и раньше, использует `npm install --legacy-peer-deps`.

## Что ещё не проверено и не реализовано

- Docker build/compose не запускались: Docker в среде отсутствует.
- YOLO, настоящий видеоанализ, отдельный видеоклассификатор и настоящий NLP-инференс
  в этом этапе не выполнялись. Работоспособность интеграции с подменой не означает
  подтверждённую работоспособность или точность обученных моделей.
- Исходная NLP-предобработка, соответствие словаря классификатору и смысл классов
  по-прежнему требуют исходников и контрольных материалов бакалаврской работы.
- `artifacts` поддерживает метаданные, но автоматическая регистрация выходных файлов
  и универсальное скачивание артефактов не реализованы. Сейчас адаптеры возвращают `[]`;
  прежние файловые результаты видео сохраняются существующим конвейером.
- Операция извлечения движений не объединена с отдельным `/api/predict`.
- Новые модели для рисунков, аудио и документов не добавлены. Примеры в инструкции
  не регистрируются как работающие модели.
- Основа хранения из `STAGE2_MATERIALS.md` в присланном ZIP отсутствовала; переносить
  невидимые исходники или считать тот этап присутствующим здесь нельзя.

## Как обновить

1. Сохранить резервную копию текущей SQLite и пользовательских файлов.
2. Перенести исходники из ZIP в существующий проект, сохранив его Compose project name
   и прежние тома. В ZIP нет node_modules, базы и пользовательских материалов.
3. В той же папке выполнить:

```bash
docker compose up -d --build ml-service bff frontend
```

Не выполнять `docker compose down -v`: эта команда удаляет тома.

## Ручная проверка после запуска Docker

1. Войти в существующий аккаунт, проверить материалы и профили.
2. Открыть «Анализ» у TXT и видео: каталог должен показать техническую готовность
   каждой модели или причину недоступности.
3. На контрольном материале выполнить реальный запуск, проверить статус, model/version,
   все параметры, полный JSON и сохранение результата после повторного открытия.
4. Для видео отдельно открыть прежний «Результат» и воспроизведение; проверить прогресс,
   выходные features/видео и отдельный вызов классификатора.
5. Под другим тестовым аккаунтом проверить недоступность чужой истории и статуса результата.
6. Проверить существующую историю старого формата и повторный запуск с записью ошибки.
