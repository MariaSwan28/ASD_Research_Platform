# Запуск демонстрационной версии этапа 15

В редакции этапа 16 добавлены роли и кабинет администратора. Перед обновлением прочитайте `STAGE16_ROLES.md`; порядок запуска Docker ниже сохраняется.

Приложение сохраняет материалы и историю в SQLite и Docker volumes. Изменения исходников не требуют удаления данных. Перед обновлением сделайте резервную копию. Никогда не выполняйте `docker compose down -v` для рабочей установки.

## Обновление в Windows

1. Распакуйте ZIP во временную папку. Перенесите исходники в прежнюю папку проекта. Не заменяйте свои .env и не удаляйте Docker volumes.
2. Из корня проекта создайте или дополните конфигурацию:

```powershell
python scripts/setup_env.py
```

Если Python на Windows не установлен, можно выполнить локальный PowerShell-скрипт:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_env.ps1
```

Скрипт создаёт случайные секреты и начальную демоучётную запись. Секреты не печатаются. Логин и пароль находятся в закрытом файле `.env` в строках SUPERUSER_LOGIN и SUPREUSER_PASS. Не отправляйте .env в чат и не публикуйте его. При обновлении старой установки пароль стандартной учётной записи admin@mail.ru с прежним известным паролем заменяется на SUPREUSER_PASS, существующие материалы этого аккаунта сохраняются. Учётные записи с собственными паролями не изменяются.

3. Соберите и запустите:

```powershell
docker compose up -d --build
docker compose ps
```

Первое построение ML-образа загружает зависимости и может занять заметное время. Контейнер ML использует Gunicorn и два Python-окружения: sklearn 1.2.2 для текста и 1.3.0 для видео. Дополнительных серверов или очередей нет.

4. Откройте http://localhost:3000/autmama/ и обновите страницу Ctrl+F5. Порты 5000 и 5010 больше не публикуются — API доступен через тот же адрес приложения.
5. Проверьте текст, короткое видео с человеком и звуковой дорожкой, историю, обработанное видео и второй аккаунт.

## Поведение моделей

- Рассказ разбивается на предложения, очищается, лемматизируется и классифицируется. Итог — доля фрагментов класса 1 и три диапазона из исходной методики. Это не вероятность РАС. Предложения без слов из словаря не получают отрицательную метку; они отмечаются как неоценённые.
- Видео: поза → характеристики → классификатор → сохранённый результат. Random Forest используется по умолчанию. Переключение на имеющийся Gradient Boosting: VIDEO_CLASSIFIER=gradient_boosting в .env и пересоздание ML-контейнера.
- Третий адаптер «Звуковая активность» работает с аудио и звуком видео. Он выделяет участки повышенной громкости, не распознаёт вокализации и не оценивает диагноз.
- Если часть видеообработки не завершилась, возвращается статус partial, а уже полученные характеристики и файлы сохраняются.
- Каждый новый видеозапуск имеет свой каталог и собственные артефакты. В отчёте можно открыть обработанное видео выбранного запуска. Старые результаты до этого этапа сохраняют прежние ссылки на последнюю обработку.

## Быстрая техническая проверка

При установленном Node.js можно проверить существующую демоучётную запись, чьи данные читаются из .env:

```powershell
node scripts/smoke_test.mjs --register
```

В редакции 16.3 для проверки материалов нужен родитель (SMOKE_EMAIL/SMOKE_PASSWORD) либо --register при открытой регистрации. Администратор не имеет личного пространства. Скрипт создаёт временный профиль и текст, выполняет анализ, читает историю и проверяет наличие третьего адаптера. Затем удаляет временные материалы. Это проверка выполнения, а не качества модели.

Для теста на сервере:

```bash
SMOKE_URL=https://your-domain.example node scripts/smoke_test.mjs --register
```

`--register` используется только в локальной установке с открытой регистрацией; создаёт отдельный тестовый аккаунт.

## Резервная копия и перенос

Скриптам нужен Python 3 и Docker Compose. Они работают в Windows и Linux:

```powershell
python scripts/backup.py
```

На время снимка останавливаются BFF и ML, затем автоматически запускаются. Архивы включают базу SQLite вместе с WAL, исходные материалы, аватары и все результаты. private.env содержит секреты и должен храниться отдельно от публичных файлов. Скопируйте папку резервной копии на независимый носитель или другое устройство.

Восстановление заменяет активные данные; сначала сохраните их текущую копию:

```powershell
python scripts/restore.py backups/ИМЯ_СНИМКА --confirm-restore
```

Секреты из private.env автоматически не восстанавливаются. Для переноса в Timeweb используйте инструкции deploy/TIMEWEB.md и параметр `--compose compose.timeweb.yml`.
