## Ограничения голосового ввода

- Функция зависит от браузера, его политики, разрешения на микрофон и поддержки русского распознавания. Во многих версиях Firefox функция не поддерживается. В Chrome/Edge может использоваться облачный сервис производителя браузера, а значит аудио может направляться этому поставщику.
- Перед первым использованием родитель сознательно нажимает «Диктовать» и разрешает микрофон. **Приложение не сохраняет аудиофайл**; в хранилище попадает только проверенный и подтверждённый родителем текст.
- Для публичного приложения с чувствительными детскими данными рекомендуем отдельно обсудить локальное или серверное распознавание в контролируемой инфраструктуре с явным согласием и правовым анализом. Реализованный вариант — локальный демонстрационный прототип по удобству ввода, но не гарантия локального распознавания.

## Унификация результатов ML — рекомендуемый контракт

Единообразие не означает, что видео, текст и аудио должны иметь одинаковые показатели. Предлагается расширить текущий API стандартизованным **представлением** поверх существующего исходного результата:

```json
{
  "schema_version": "1.0",
  "model": { "id": "audio-example", "version": "1.0", "label": "Анализ речи", "modality": "audio" },
  "material": { "fileId": "...", "childProfileId": "..." },
  "status": "completed",
  "analyzed_at": "2026-11-05T15:00:00Z",
  "summary": { "title": "Анализ завершён", "description": "Выявлены особенности речевой активности" },
  "sections": [
    { "id": "speech", "title": "Речевая активность", "type": "metrics", "items": [
      { "key": "speech_duration", "label": "Длительность речи", "value": 12.5, "unit": "с" }
    ]},
    { "id": "timeline", "title": "Фрагменты записи", "type": "events", "items": [] }
  ],
  "limitations": ["Исследовательская модель, не предназначена для диагностики"],
  "raw_result": { "arbitrary": "original adapter JSON; unchanged" }
}
```

**Это дизайн будущего контракта, не уже реализованный формат backend.** На данном этапе пользовательский UI умеет отображать произвольный JSON результата, а сервер по-прежнему сохраняет исходный JSON без потерь. Следующий шаг — согласовать типы `sections` и постепенно приспособить адаптеры к этому контракту, сохранив старые результаты.

### Из первоначальной видеоверсии

`VideoAnalyticsModal.jsx` оригинального MERN_ASD_SHARE использует:

- `video_metadata`: длительность, разрешение, FPS, число кадров, дата записи;
- `aggregated_features`: число резких движений, движения в минуту, метрики симметрии, другие агрегированные признаки;
- `preliminary_annotation`: предварительная оценка, факторы и метка;
- `quality_metrics`: полнота/качество обнаружения ключевых точек, пропуски кадров;
- `mlPrediction`, `ml_insights`: предсказание, уверенность, распределение, сравнительные/комбинированные оценки;
- итоговые блоки рекомендаций и подробностей.

Все эти разделы должны сохраняться. В действующей исходной верстке есть *клинически категоричные* формулировки (например, «Диагностика», «Высокий риск РАС»). Перед пилотным применением с родителями их следует переименовать в нейтральные описания технического результата модели, не выдающие его за клиническую оценку.

## Обновление без потери данных

1. Сохраните копию рабочего каталога и Docker volumes/базы данных. Не используйте `docker compose down -v`.
2. Распакуйте новый ZIP **в ту же папку проекта**, сохраняя существующее имя каталога/Compose project. В этом обновлении менялся только frontend и добавилась инструкция.
3. В текущей папке выполните `docker compose up -d --build frontend`.
4. Обновите страницу (`Ctrl+F5`). Проверьте порядок блоков и одинаковую подпись «Анализ», голосовой ввод (если браузер поддерживает) и существующие результаты.

Если голосовой ввод не поддерживается, поле ввода текста работает как обычно. Запись звука в приложении не реализована — речь непосредственно распознаётся средствами браузера.
