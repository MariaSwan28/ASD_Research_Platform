# ASD Research Platform — этап 3: профили детей

## Что добавлено

- Новая таблица `ChildProfiles`: владелец (`ownerId`), имя/псевдоним, необязательные дата рождения и заметка.
- Защищённые JWT-маршруты: `GET /api/children`, `POST /api/children`, `PATCH /api/children/:id`, `DELETE /api/children/:id`.
- Новое необязательное поле `Files.childProfileId`. При запуске BFF выполняется точечная миграция SQLite, сохраняющая старые записи. Старые файлы остаются в разделе «Общие материалы».
- Интерфейс выбора, создания, редактирования и удаления профиля; удаление профиля с файлами запрещено.
- Запрос списка файлов фильтруется по профилю; новая загрузка, включая загрузку по частям, сохраняет `childProfileId` после серверной проверки владельца.
- Файлы детей разделены также по физическим каталогам `/app/files/<user-id>/children/<child-id>/...`, что исключает конфликт одинаковых имён между детьми.
- После видеоанализа создаётся запись `AnalysisRecords` со ссылками на пользователя, профиль и файл. Содержимое существующего ответа ML остаётся прежним, в `fileInfo` добавлена ссылка на профиль.
- Теги («Удары», «Вскрики») и существующий формат вывода результатов ML сохранены.
- Обновлено оформление окна тегов, формы текстового наблюдения, всплывающих окон ссылок/папок, просмотра видео и аналитики; структура аналитического результата не менялась.
- Просмотр обработанного видео требует JWT; для демонстрации видео сначала загружается в Blob браузера. Для больших видеозаписей в будущем лучше реализовать безопасный потоковый просмотр.

## Запуск и сохранение данных

1. Сделайте **резервную копию рабочей папки и SQLite**. Для SQLite при активной БД используйте штатный `.backup` либо остановите приложение перед копированием согласованного набора файлов.
2. Остановите старый проект командой `docker compose down` из его папки, **без `-v`**.
3. Распакуйте архив. В новой папке выполните `docker compose up -d --build`.
4. Откройте `http://127.0.0.1:3000/autmama/`.
5. Создайте два профиля детей. Поочередно выбирайте профиль, загружайте тестовые PNG/TXT/MP4 с тегами и убедитесь, что списки раздельны.
6. Вернитесь в «Общие материалы» — там должны оставаться старые загрузки.
7. Проверьте вход/выход, скачивание и вывод аналитики тестового видео.

**Важно:** имя каталога Compose-проекта влияет на имя Docker volumes. Если новая распакованная папка называется иначе, старые файлы и SQLite могут оказаться в томах предыдущего Compose-проекта. Не удаляйте volumes; при миграции потребуются сохранённые volume names или перенос данных. Для демонстрации можно начать с новой пустой БД.

## Ограничения

- Пока нет S3 и Timeweb Cloud, данные остаются в локальной SQLite и файловом хранилище Docker.
- Модуль NLP из бакалаврской работы ещё не подключён.
- Составной механизм регистрации/замены ML-моделей пока не реализован; этот этап касается профилей и интерфейса.
- Защита исходного приложения ещё требует отдельного аудита; не публикуйте тестовую сборку с фиксированными JWT-секретами и известным административным паролем в интернет.
- Не загружайте реальные медицинские данные детей в демонстрационную сборку.
- Выполнены синтаксические проверки; полноценная сборка React и Docker здесь недоступна. Итоговые функциональные сценарии нужно проверить локально.
