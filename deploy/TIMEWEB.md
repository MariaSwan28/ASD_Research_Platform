# Развёртывание в Timeweb Cloud

Назначение конфигурации — закрытая демонстрация предзащиты на облачном виртуальном сервере с Docker Compose. Используется одна VM и постоянные volumes; переход на Kubernetes или внешнюю СУБД не требуется. Это конфигурация облачного сервера, а не автоматически переносимого приложения App Platform.

## Что требуется от владельца сервера

- Созданный облачный сервер x86_64 с Linux и Docker Engine / Docker Compose v2.
- SSH-доступ владельца сервера. Закрытые ключи и пароли не отправлять в чат или в репозиторий.
- Домен или поддомен с A-записью на публичный IPv4 сервера. Если есть AAAA-запись, IPv6 тоже должен вести на этот сервер, иначе её нужно исправить.
- Доступные извне TCP 80/443 для сайта и сертификата. SSH 22 разрешать только с административных адресов. Порты 3000/5000/5010 наружу не открываются.
- Объём памяти и CPU проверяется реальным запуском видео: нагрузочный тест на сервере пока не выполнен. Размер серверного диска должен учитывать исходные файлы, отдельные результаты каждого запуска, Docker-образы и резервные копии.

Официальные инструкции:
- https://timeweb.cloud/docs/cloud-servers/manage-servers/create-server
- https://timeweb.cloud/docs/firewall
- https://timeweb.cloud/docs/domains/subdomains
- https://caddyserver.com/docs/automatic-https

## Установка

1. Загрузить исходники в отдельный каталог, например `/opt/asd-platform`. Не загружать node_modules, локальные окружения Python, build и личные .env в общедоступное место.
2. Из этого каталога создать секреты и задать домен:

```bash
python3 scripts/setup_env.py --domain your-domain.example --admin-email your-email@example.com
```

Значения логина и пароля начальной учётной записи сохраняются в .env. Проверить этот файл локально на сервере и сохранить пароль в менеджере паролей. Не публиковать .env.

3. Проверить DNS и доступность портов, затем:

```bash
docker compose -f compose.timeweb.yml config --quiet
docker compose -f compose.timeweb.yml up -d --build
docker compose -f compose.timeweb.yml ps
```

Наружу публикуется только Caddy на 80/443. Он получает и продлевает HTTPS-сертификат и проксирует запросы во внутренний Nginx. BFF и ML доступны только в Docker-сети. Межсервисный ML API дополнительно проверяет X-ML-Token. Caddy не требует отдельной Python-инфраструктуры.

4. Открыть `https://your-domain.example/autmama/`, войти, выполнить сценарий START_HERE_STAGE15.md.
5. Проверить с другого устройства: 5000/5010 недоступны, HTTP перенаправляется на HTTPS, чужой аккаунт не видит профили/файлы/артефакты.
6. Проверить перезапуск контейнеров и резервное восстановление на отдельной тестовой установке.

Регистрация в серверном Compose отключена. Для демонстрации используется созданная учётная запись; открывать регистрацию реальных родителей до завершения серверной проверки не следует. Локальный Compose оставляет самостоятельную регистрацию для проверки двух аккаунтов.

## Перенос существующих материалов из Windows

1. В старой папке проекта выполнить `python scripts/backup.py`.
2. Передать полученную папку снимка на сервер по защищённому каналу.
3. На сервере собрать образы и создать контейнеры командой up, затем выполнить:

```bash
python3 scripts/restore.py /path/to/snapshot --compose compose.timeweb.yml --confirm-restore
```

Скрипт проверяет контрольные суммы, останавливает писателей, очищает соответствующие volumes, восстанавливает снимок и запускает сервисы. private.env не заменяет новую серверную конфигурацию автоматически. После восстановления войдите с прежней пользовательской учётной записью и прежним паролем. Если SUPERUSER_LOGIN уже существует в восстановленной базе, её пароль не заменяется автоматически новым SUPREUSER_PASS. Если нужен новый серверный демоаккаунт, перезапустите BFF, чтобы он выполнил безопасное создание при старте.

Старый volume ml-models больше не подключается: доверенные модели берутся из построенного образа. Этот старый volume не удаляется автоматически. Пользовательские volumes shared-files, shared-dataset, bff-data, bff-static сохранены по назначению. При восстановлении проверяйте имя Compose-проекта, не удаляйте volumes существующего проекта.

## Обслуживание

```bash
python3 scripts/backup.py --compose compose.timeweb.yml
docker compose -f compose.timeweb.yml logs --tail=100 bff ml-service gateway
```

Резервные копии нужно выносить с этой VM. Для регулярного резервного копирования настройте серверный планировщик после успешного контрольного восстановления. Скрипты не добавляют расписание автоматически.

Проверка готовности контейнера означает, что HTTP-процесс отвечает; она не заменяет прогон моделей. Публичное размещение с реальными детскими материалами требует отдельного решения по доступам, хранению, резервированию и правилам использования данных. В текущем релизе целевой сценарий — закрытая предзащита на демонстрационных материалах.
