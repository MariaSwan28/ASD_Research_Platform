# Версия 16.1 — ФИО и поля форм

Историческое описание. В версии 16.2 администратор также создаёт родителей и управляет детьми; поле «Имя в кабинете» убрано. Актуальная инструкция — `STAGE16_2_ADMIN.md`.

## Изменения

- Самостоятельная регистрация создаёт только родителя. Выбора роли в форме нет; попытка передать другую роль через API отклоняется.
- Администратор создаёт только специалистов, указывая ФИО, почту и пароль. Родительские аккаунты через административную форму больше не создаются. Существующее управление ролями остаётся доступным только администратору, с ограничениями предыдущей версии.
- ФИО добавлено всем пользователям, включая администратора, и детям. Новые родители и специалисты заполняют его при создании аккаунта, родители — при создании/редактировании профиля ребёнка.
- Пользователь может заполнить или изменить своё ФИО в «Мой профиль». Администратор может исправить ФИО пользователя в списке пользователей.
- У ребёнка сохраняется отдельное необязательное «Имя в кабинете». Основной заголовок — ФИО; у старых записей без ФИО временно показывается прежнее имя.
- В назначениях отображаются ФИО специалистов и родителей с почтой; специалист видит ФИО только закреплённых детей. Материалы и результаты для специалиста по-прежнему закрыты.
- Убрана глобальная фиксированная высота 30 px у select. Поля и выпадающие списки получили достаточную высоту и отступы, а поля назначения — достаточную ширину. Чекбоксы и загрузка файлов не увеличиваются.

## Обновление

Перед обновлением создайте резервную копию. Распакуйте полный архив, перенесите исходники в существующую папку проекта, сохранив свой `.env` и Docker volumes. Из корня выполните:

```bat
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

После запуска обновите страницу Ctrl+F5 и повторно войдите. `SUPERUSER_LOGIN` остаётся администратором; пароли не меняются. Миграция автоматически добавляет поле `fullName` в Users и ChildProfiles. Существующие профили, материалы, заметки, роли и назначения сохраняются; вымышленные ФИО им не присваиваются.

Если у существующего пользователя ФИО отсутствует, заполните его в личном профиле либо через кабинет администратора. ФИО ребёнка заполняет владелец через редактирование карточки.

Для Timeweb используйте `docker compose --env-file .env -f compose.timeweb.yml up -d --build`. В этой редакции самостоятельная регистрация родителей по умолчанию включена и в облачной конфигурации. Для закрытой демонстрации её можно выключить через `ALLOW_REGISTRATION=false` в `.env` и пересоздать BFF. Специалисты самостоятельно зарегистрироваться не могут ни при какой настройке регистрации.

Не выполняйте `down -v`: эта команда удаляет тома с данными.

## Проверка

1. Откройте регистрацию: должно быть поле «ФИО родителя», без выбора роли. После регистрации роль — родитель.
2. Администратором создайте специалиста с ФИО; назначьте его ребёнку. Списки должны показывать выбранные значения целиком по высоте, а назначения — ФИО с почтой.
3. Родителем создайте/отредактируйте ФИО ребёнка. Специалистом проверьте доступ к этому ФИО и дате рождения, без заметок и результатов.
4. В личном профиле измените ФИО, выйдите и войдите снова: значение должно сохраниться. Проверьте редактирование ФИО пользователей администратором.
5. Проверьте выпадающие списки регистрации, ролей, назначений и выбора модели, в том числе при узком окне браузера.

Production-сборка проходит с предупреждениями старой версии.

Дополнительно BFF проверен на копии тестовой базы версии 16: обновление схемы, сохранение паролей/ролей/профилей/назначений/заметок, заполнение ФИО и сохранение после перезапуска.
