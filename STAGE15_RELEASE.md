# Этап 15 — демонстрационный релиз и подготовка Timeweb Cloud

Этот этап завершает общую реализацию анализа, хранения и серверной конфигурации в одном архиве. Он не означает, что сервер Timeweb уже создан или что удалённое развёртывание проверено. Код не переписан с нуля: сохранены React, Node.js, Flask, SQLite, Docker, профили детей, теги и текущий дизайн.

## Реализовано

### Текстовый анализ

Восстановлена обработка по описанию исходной работы: разделение на предложения, нижний регистр, очистка, лемматизация pymorphy3, локальный список русских стоп-слов NLTK, CountVectorizer и Naive Bayes. Нормализованные предложения классифицируются раздельно. Итог — среднее бинарных меток, диапазоны <=0.4 / <=0.6 / >0.6 и таблица предложений. Это доля фрагментов класса 1, не вероятность РАС.

Предложения без признаков словаря не заменяются нулевой меткой и не включаются в знаменатель; число таких предложений сохраняется. Версия адаптера: bachelor-2024-count-sentences-v2. Разделение реализовано регулярным выражением, поэтому это воспроизведение методики по описанию, а не доказанная побитовая эквивалентность исходному приложению. Исходного датасета для оценки качества здесь нет.

### Полный видеоадаптер

Универсальный запуск теперь последовательно извлекает движения и вызывает обученный классификатор. Несовместимые sklearn изолированы: основной Python использует 1.2.2, отдельный процесс внутри того же контейнера — 1.3.0. Сохранённые модели проверяются по фиксированным SHA-256; путь модели не принимается от пользователя. Проверены загрузка и инференс Random Forest и Gradient Boosting.

Классы возвращаются по фактическому model.classes_. Вероятности и уверенность сохраняются без медицинской интерпретации. Точное преобразование JSON в признаки вынесено в общий movement_features.py и используется также исходным тренером.

У моделей есть 8 признаков ручной разметки, которых нет у нового видео. Сохранено исходное правило заполнения отсутствующих колонок нулями, но список всех заменённых признаков явно записывается в defaulted_features. Это существенное ограничение переноса модели на новые записи, которое нельзя выдавать за клиническую точность. Восстановление модели не означает устранение этого ограничения.

### История и артефакты

Каждый новый запуск пишет в отдельный каталог dataset/<owner>/runs/<analysis_id>. Обработанное видео, JSON и NPZ зарегистрированы в manifest.json и связаны с сохранённой записью анализа. Публичный ответ содержит только идентификаторы артефактов. Скачивание проверяет владельца результата и исходного материала, а также фактический путь файла внутри каталога запуска. В карточке можно открыть видео именно выбранного запуска.

Просмотр старого API /feature больше не запускает классификатор и не читает общий каталог результатов по одному имени. Совместимый маршрут /start-analyze направлен в общий механизм сохранения. Прежняя история не переписывается.

### Контракт 1.2

Поля 1.1 сохранены; добавлен статус partial для частично выполненной обработки. Если извлечение характеристик успешно, а классификатор завершился ошибкой, сохраняются характеристики и артефакты, а error объясняет неполный результат. completed требует error=null; failed не содержит успешных параметров. Node и React читают 1.0/1.1/1.2. Новые адаптеры декларируют 1.2.

### Третий адаптер

Добавлен audio-activity-v1: извлечение звука FFmpeg, RMS-энергия, интервалы повышенной громкости и их суммарная длительность. Это алгоритмический адаптер, не обученная модель распознавания вокализаций. Он не различает речь, вокализации и шум. Записи ограничены 10 минутами.

scripts/adapter_demo.py в отдельной временной копии добавляет только audio_activity.py: реестр меняется с двух адаптеров на три. Хеши React, контроллеров и маршрутов BFF до/после остаются одинаковыми. Доказательство — demo/verification.json. Это проверка расширяемости интерфейса, а не качества третьей ML-модели.

### Универсальное хранение

Обычная и частичная загрузки используют один saveMaterial. Проверяются имя, владелец/ребёнок/папка, фактический размер, уникальные индексы частей и текущая квота внутри SQLite-транзакции. Повтор части идемпотентен. Часть с неверным размером или индексом отвергается. Нельзя закончить файл за счёт повторения одного индекса.

Добавлены MIME-тип и категория, безопасная добавочная миграция и заполнение метаданных существующих строк. MIME определяется по известному расширению; это метаданные хранения, не универсальная экспертиза содержимого. Исходные файлы не выполняются и выдаются с проверкой доступа. Добавлен фильтр типов в списке; папки остаются доступными для навигации.

### Серверная подготовка

- Два независимых Compose-файла: локальный и Timeweb. Внутренние порты BFF/ML не публикуются; на сервере открыт только HTTPS-шлюз Caddy.
- Секреты генерируются setup_env.py / setup_env.ps1, не зашиты в Compose. Старая стандартная админучётка с известным паролем ротируется с сохранением данных.
- Межсервисный токен, ограничения тела запросов/файлов, защита путей, ограничение запросов входа и анализа, secure cookies на сервере, закрытая серверная регистрация.
- Загрузка файлов проверяет JWT до обработки multipart; временные файлы очищаются после ответа. Аватары ограничены JPEG/PNG и размером 2 МБ.
- Gunicorn: один процесс с потоками, чтобы сохранить единый контроль видеоанализа. Длинные таймауты согласованы между клиентом, BFF, Nginx и Gunicorn.
- Node-образы переведены на 22; lock-файлы согласованы для npm ci. ML-образ использует Python 3.10 / Debian Bookworm.
- Healthchecks, ограничение объёма логов, скрипты согласованного резервного копирования и восстановления SQLite и файлов.

## Не подтверждено в этой среде

Docker-демон недоступен. Поэтому не выполнены сборка образов и полный запуск Compose, настоящий ролик через YOLO в контейнере, визуальная проверка браузером, HTTPS/DNS на Timeweb и реальное восстановление Docker volumes. Node-тесты выполнялись на 24, тогда как Dockerfile использует 22; совместимость конкретного образа должна быть подтверждена первой сборкой. Нельзя считать перечисленное пройденным только по наличию конфигурации.

Для окончательного серверного прогона нужны адрес VM, домен и безопасно настроенный доступ к серверу владельца. Пароли и закрытые SSH-ключи не должны передаваться в переписке. До завершения этого прогона целевой сценарий — закрытая демонстрация, а не публичный сервис с реальными материалами детей.
