# Версия 16.3 — шапка и границы кабинета администратора

- Имя/ФИО и роль убраны из шапки. Для учётной записи остаются «Выход» и иконка профиля.
- У администратора нет личного пространства, ссылки «Мои материалы», загрузки файлов или запуска анализов. Прямой переход на `/autmama/materials` возвращает его в кабинет администратора.
- Детей создают только родители. У администратора нет кнопки создания ребёнка; сервер отклоняет создание через обычный и административный API.
- Администратор по-прежнему добавляет, редактирует и удаляет родителей и специалистов, редактирует/удаляет существующие профили детей, назначает и снимает специалистов. Настройки своей учётной записи доступны через иконку профиля.
- Специалист видит только закреплённые профили; доступ к материалам и результатам для него не открыт.

## Обновление

Сохраните резервную копию и существующий `.env`. Перенесите исходники полного архива в прежнюю папку проекта. Выполните:

```bat
docker compose --env-file .env up -d --build
docker compose --env-file .env ps
```

Обновите страницу Ctrl+F5 и повторно войдите. Не используйте `down -v`. Дополнительные миграции по сравнению с 16.2 не требуются. Прежние материалы, включая старые материалы административного аккаунта, физически не удаляются; личный доступ администратора к ним через платформу закрыт.

Для Timeweb используйте `-f compose.timeweb.yml` перед `up`/`ps`.

## Проверка

1. В любой роли проверьте шапку: справа только выход и иконка профиля.
2. Администратором проверьте разделы родителей, специалистов и детей. Ссылки на личные материалы и кнопки создания ребёнка быть не должно.
3. Попробуйте открыть `/autmama/materials` администратором — должен открыться административный кабинет.
4. Родителем создайте ребёнка и загрузите материал. Администратором отредактируйте этот профиль и назначьте специалиста.
5. Специалистом проверьте просмотр закреплённого профиля.

Техническая проверка материалов `scripts/smoke_test.mjs` теперь требует учётную запись родителя через `SMOKE_EMAIL`/`SMOKE_PASSWORD`. При открытой регистрации можно использовать `node scripts/smoke_test.mjs --register`, чтобы создать временного родителя. Учётная запись администратора из `.env` для этого сценария не подходит; скрипт выдаёт понятное сообщение перед созданием материалов.
