## Что удалось установить без небезопасной десериализации
`MachineNB1.pickle` — объект sklearn GridSearchCV с классификатором MultinomialNB, сохранённый scikit-learn 1.2.2. У обученного классификатора `n_features_in_ = 3246`.

**Важный блокер:** файл НЕ содержит обученный TF-IDF векторизатор. Классифицировать произвольные тексты без исходного словаря и полностью той же предобработки нельзя: модель ожидает вектор из 3246 признаков, а не строку.

Нужно найти в бакалаврских материалах `TfidfVectorizer.pickle` / `vectorizer.pkl` / `tfidf.pkl` либо исходный корпус и точный скрипт обучения/предобработки (чтобы восстановить конвейер). Не обучать векторизатор на случайном тексте — результат недостоверен.

Даже после получения векторизатора необходимо проверить версии Python/scikit-learn, SHA-256 доверенного файла и контрольные примеры. Только затем разработчик может включить `ENABLE_TRUSTED_TEXT_PICKLES=1` локально. Pickle-файлы потенциально выполняют код при загрузке — не принимать их от пользователей.

## Запуск
В новой папке `docker compose up -d --build`. При смене папки Compose изменит имя проекта и могут создаться новые тома; сохраните прежние данные. Не используйте `docker compose down -v`.

Проверка: авторизуйтесь, откройте «Мои материалы», найдите «Возможности анализа». Текстовая модель отображается как недоступная до восстановления векторизатора. Это правильно, а не ошибка развертывания.

API возвращает `503` с `reason=missing_vectorizer`, а не фальшивое предсказание. Запросы идут через BFF с проверкой авторизации; прямой порт Python-сервиса всё ещё открыт в Docker Compose исходного прототипа и должен быть закрыт перед публикацией.

## Тестирование
Проверить вход, выход, профили детей, теги, загрузку файлов, существующий анализ видео. Приложение пока не годится для публичной загрузки данных детей без завершения аудита безопасности.
