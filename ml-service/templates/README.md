# Подключение модели и описание отчёта

Платформа использует Python-адаптеры. Для каждого нового адаптера разработчик задаёт вход, вызов модели и **состав отчёта**. Отдельный контейнер или изменение React для поддерживаемых блоков не нужны.

## Что предоставить

1. Доверенные файлы модели, её зависимости и исходную предобработку.
2. Адаптер: `MODEL`, `status()` и `analyze(payload)`. В готовом шаблоне вызов разделён на `infer()` и `present()`.
3. Описание блоков `MODEL['report_schema']` и результат в формате 1.3.
4. Контрольный пример с ожидаемыми исходными значениями. Унификация отчёта сама по себе не подтверждает точность модели.

Скопируйте `adapter_template.py` в `core/ml_adapters/my_model.py`, реализуйте код и проверки готовности, затем установите `IMPLEMENTED = True`. Добавьте зависимости/артефакты в сборку ML-сервиса. Новый модуль обнаруживается автоматически после пересборки.

## Описание модели

Обязательны уникальный `id`, `label`, `version`, `modality`, непустые списки `input_types` и `extensions`, `operation`, `result_schema_version='1.3'` и `report_schema`.

`status()` возвращает `('configured', None)` или `('unavailable', 'Причина')` без запуска модели. Текст поступает в `payload['text']`, проверенный сервером путь — в `payload['file_path']`. Не принимайте от пользователя файлы исполняемых моделей и произвольные пути.

## Состав отчёта

```python
MODEL['report_schema'] = {
    'version': '1.0',
    'blocks': [
        {'id': 'summary', 'type': 'text', 'title': 'Итог анализа', 'required': True},
        {'id': 'counts', 'type': 'table', 'title': 'Подсчёты', 'required': True,
         'columns': [{'key': 'name', 'label': 'Показатель'},
                     {'key': 'count', 'label': 'Количество', 'unit': 'шт.'}]},
        {'id': 'plot', 'type': 'image', 'title': 'График', 'required': False,
         'media_types': ['image/png']}
    ]
}
```

Порядок массива `blocks` — порядок отображения. Для трёх изображений объявите три блока с разными `id`. Название и пояснение `description` задаёт разработчик. `required` обязателен у каждого блока. Идентификаторы блоков/файлов — до 80 символов, латинские буквы, цифры, `.`, `_`, `-`, первый символ — буква или цифра. Допустимо до 100 блоков и до 50 столбцов таблицы.

| type | Что передать | Как отображается |
|---|---|---|
| text | Непустая строка | Обычный многострочный текст, без выполнения HTML |
| table | Список строк-объектов; столбцы описаны в схеме | Таблица; большие наборы показываются порциями без удаления данных |
| image | Идентификатор зарегистрированного PNG/JPEG/WebP | Изображение; график заранее строится кодом адаптера |
| audio | Идентификатор зарегистрированной записи | Кнопка открытия и аудиопроигрыватель |
| video | Идентификатор зарегистрированного видео | Кнопка открытия и видеопроигрыватель |
| file | Идентификатор зарегистрированного файла | Скачивание, например JSON, CSV или NPZ |

У таблицы обязательны `columns` с `key` и `label`, при необходимости `unit`. Ячейки — строки, числа, boolean или null; вложенные объекты в ячейках не используются. Пустая таблица `[]` допустима, например когда звуковых участков нет. Не подменяйте отсутствие данных нулём; сохраняйте 0 и false как реальные значения. NaN и бесконечность недопустимы. SVG/HTML как изображения не поддерживаются.

## Что вернуть после анализа

```python
from core.result_contract import make_result
from core.report_contract import text_block, table_block, file_block

return make_result(
    conclusion={'code': 'processed', 'title': 'Обработка завершена',
                'explanation': 'Показатели рассчитаны.'},
    metrics=[], limitations=[], raw_output=raw,
    report_blocks=[
        text_block('summary', 'Обработка завершена. Найдены три события.'),
        table_block('counts', [{'name': 'События', 'count': 3}]),
        file_block('plot', image_artifact['id'])
    ],
    artifacts=[image_artifact]
)
```

Это образец сборки; `raw` и `image_artifact` получают в вашем коде анализа и сохранения файла. Четыре прежних поля `conclusion`, `metrics`, `limitations`, `raw_output` сохраняются. У показателей `metrics` обязательны key, label, type, value, description; unit — по необходимости. `parameters` и неизвестные исходные поля остаются в технических подробностях. Расшифровку классов задаёт конкретный адаптер, платформа её не придумывает.

`text_block`/`table_block`/`file_block` передают значения по id блока. Можно передать `unavailable_block(id, 'Причина')`, если блок не получен. Исполнитель сам добавляет статусы и сохраняет снимок схемы в `result['report']`. Не собирайте `analysis_id`, время или пользовательские пути вручную.

## Сохранение изображений и записей

```python
from core.run_artifacts import run_directory, register_artifact

image_path = run_directory(payload) / 'images' / 'plot.png'
image_path.parent.mkdir(parents=True, exist_ok=True)
# Здесь ваш код строит график и сохраняет его в image_path.
image_artifact = register_artifact(
    payload, image_path, 'plot-file', 'График', 'image/png'
)
```

Файл должен существовать внутри каталога текущего запуска. `register_artifact` записывает его в manifest.json и возвращает метаданные для `artifacts`. В отчёте используется только id, а не путь или внешний URL. Не используйте произвольные общие папки «последнего результата». Платформа проверяет владельца, запуск, MIME-тип, существование и границы пути. Для графиков используйте PNG/JPEG/WebP; интерфейс не выбирает оси и не строит график из таблицы самостоятельно.

## Неполный результат и совместимость

Если обязательного блока или его файла нет, сохраняются полученные данные, а запуск получает `partial` и сообщение о неполном отчёте. Отсутствующий необязательный блок сам по себе не делает результат частичным. Неверные типы, неизвестные/повторяющиеся id и ссылки на необъявленные файлы считаются ошибкой контракта. Полная ошибка модели остаётся `failed`.

Снимок схемы сохраняется вместе с результатом. Изменение адаптера не перестраивает старый отчёт. Старые результаты 1.0–1.2 читаются прежним интерфейсом; новые адаптеры используют 1.3. Права пользователей этой доработкой не расширяются.

## Готовый наглядный пример

`report_example.py` — технический адаптер с текстом, таблицей и тремя изображениями. Он находится вне каталога обнаружения и не появляется у пользователей как настоящая модель. В Python-окружении с зависимостями ML-сервиса из корня проекта выполните:

```bash
python scripts/report_demo.py --output-dir report-demo
```

Будут созданы report.json, три PNG и manifest.json в каталогах запуска. Пример считает символы, слова и строки входного текста, не оценивает РАС и не меняет базу платформы.

Действующие адаптеры: `parent_story.py` — сохранённые формулировки классификации и таблица фрагментов; `audio_activity.py` — интервалы, график и звуковая дорожка; `movement_video.py` — характеристики, таблица, график, обработанное видео и выгрузки.
