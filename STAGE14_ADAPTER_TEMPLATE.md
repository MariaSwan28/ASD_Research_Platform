# Этап 14 — частные адаптеры и шаблон новых моделей

Общий контракт 1.1 и интерфейс этапа 13 сохранены. Кастомизация выполняется внутри Python-адаптера, без ветвления по модели в React и без новых маршрутов Node.js.

## Выполнено

- Добавлена make_result(): проверяемый конструктор ответа с четырьмя обязательными аргументами — conclusion, metrics, limitations, raw_output. Метаданные запуска формирует общий исполнитель. Подробные параметры, предупреждения и артефакты получают корректные значения по умолчанию.
- Добавлен `ml-service/templates/adapter_template.py`: паспорт MODEL, проверка готовности status, точки infer и present, единый analyze. Шаблон не зарегистрирован как готовая модель; до реализации запуск завершается ошибкой.
- Добавлено руководство `ml-service/templates/README.md`: обязательные поля, ошибки, показатели, таблицы, порядок подключения и проверки.
- Текстовая модель стала частным случаем: 0/1 расшифровываются по дипломной работе Лебедевой, с.33; неизвестные метки обрабатываются отдельно. Результат явно относится к рассказу, а не к диагнозу ребёнка.
- В карточке текста указан фактический режим «Рассказ целиком». Доля предложений и вероятность РАС не вычисляются и не подставляются. Отсутствующее число признаков не превращается в ноль.
- Видеоадаптер стал частным случаем: параметры дополнены таблицей частот и скоростей по частям тела. Исходные значения и неизвестные поля сохранены полностью. Таблица использует уже существующий универсальный формат parameters/table.
- Разделены предварительная аннотация по правилам и итоговый классификатор. В этом адаптере классификатор пока не вызывается; это явно указано в результате.

## Что осталось отдельной работой

Этап не восстанавливает лемматизацию и анализ по предложениям, не меняет CountVectorizer на TF-IDF и не переобучает модели. Происхождение конкретных pickle ещё нужно подтвердить исходным кодом/контрольными примерами. Документированное соответствие классов показано с этим ограничением.

Ошибка совместимости scikit-learn у видеоклассификатора не исправлена. Привязка выходных видеофайлов к конкретным запускам также остаётся отдельной задачей. Настоящие модели в Docker здесь не проверялись.

## Проверки

- 19 Python-тестов — пройдены: контракт, API на заглушках, частные результаты, шаблон, ошибки и сохранность исходных полей.
- 3 Node.js-теста — пройдены, включая HTTP/SQLite и владение файлами.
- Дополнительно проверена совместимость реальных сформированных Python-ответов с валидатором BFF на текстовых классах 0/1/неизвестном и видеоответе с таблицей.
- React и маршруты BFF в этом этапе не изменялись; используются успешно проверенные и собранные компоненты этапа 13. Полный Docker-инференс и визуальная проверка браузером не выполнены.

## Применение

Сохраните свои .env, базу SQLite, files и dataset. Перенесите исходники в текущий проект и выполните из корня:

```powershell
docker compose up -d --build ml-service
```

Если этап 13 ещё не установлен, сначала обновите все три сервиса:

```powershell
docker compose up -d --build frontend bff ml-service
```

Обновите браузер Ctrl+F5. Повторный анализ создаст новый отчёт; прежняя история не переписывается. Пользовательские данные и файлы не нужно удалять. В архив включены все изменения этапов 12.1 и 13.
