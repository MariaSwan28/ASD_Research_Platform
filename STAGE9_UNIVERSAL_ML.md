# ASD Research Platform — этап 9: универсальные ML-адаптеры

## Что реализовано

- Python находит доверенные модули в `ml-service/core/ml_adapters/` автоматически.
- Каждый модуль описывает `MODEL`, `status()` и `analyze(payload)`.
- `GET /api/ml/capabilities` возвращает модели из реестра.
- `GET /api/ml/available/:fileId` возвращает совместимые с сохранённым файлом модели (по расширению файла и правам доступа).
- `POST /api/ml/analyze` с JSON `{ "fileId": "...", "modelId": "..." }` запускает выбранную модель после проверки владельца файла. Клиент **не передаёт путь к файлу**.
- `GET /api/ml/analyses/:fileId` возвращает общую историю результатов. Старые текстовые результаты дополнительно включаются для совместимости.
- Новая таблица `UnifiedAnalysisResults` хранит `ownerId`, `childProfileId`, `fileId`, `modelId`, `modelVersion`, `status`, JSON-результат и дату. Старая история не удаляется.
- Текстовый анализ теперь использует общий API; окно показывает модели из реестра. Кнопка видеоанализа тоже вызывает общий API, но старые video-endpoints оставлены для совместимости.
- Видеомодель возвращает те же данные старого алгоритма; для видео сохраняются признаки и файл анализа как прежде.

## Добавление ML-модели разработчиком

Создать Python-файл в `ml-service/core/ml_adapters/`, например `image_example.py`:

```python
MODEL = {
    "id": "drawing-v1",
    "version": "1.0",
    "modality": "image",
    "input_types": ["image/png"],
    "extensions": [".png"],
    "operation": "drawing-analysis",
    "label": "Анализ рисунка",
}

def status():
    # Проверяйте зависимости и наличие модели, прежде чем возвращать configured.
    return ("unavailable", "trained_artifact_not_installed")

def analyze(payload):
    # При новом типе payload содержит file_path, file_name, user_id.
    # Здесь должен быть настоящий проверенный алгоритм.
    raise RuntimeError("trained_artifact_not_installed")
```

**Не добавляйте этот пример как рабочую модель**: обученного анализатора рисунка у проекта нет. После добавления реального доверенного адаптера и пересборки ML-сервиса каталог пополнится автоматически; не нужно менять React, Node-маршруты или модели базы. Для `text` payload содержит `text`, для `video` — `user_id, video_path`, для прочих модальностей — `user_id, file_path, file_name`. У всех сервисов доступ к общему тому `/app/files`.

Расширения файла используются для определения совместимости, **но не являются проверкой фактического содержимого**. Перед публичным развёртыванием необходима серверная проверка допустимых файлов, расширений и MIME, ограничения ресурсов и изоляция моделей.

## Обновление без потери данных

Из **той же папки** проекта (сначала сделайте резервную копию SQLite и файлов):

```powershell
docker compose up -d --build
```

**Не запускайте `docker compose down -v`.** Запуск Compose из папки с новым названием может создать новые volumes, тогда прежние файлы не будут видны до их корректного переноса. Убедитесь, что текущая папка и имя Compose-проекта соответствуют вашей рабочей версии.

В данном этапе скрипт автоматически создаёт **новую** таблицу через Sequelize `sync()`; существующие таблицы и строки не удаляются. Тем не менее резервная копия обязательна перед изменением схемы.

## Проверка

1. Убедиться, что в разделе «Возможности анализа» перечислены видео и текст.
2. В профиле ребёнка открыть TXT и нажать «Анализ» → выбрать «Анализ рассказа родителя» → «Запустить анализ»; проверить исходную метку 0/1 и увеличение числа записей истории.
3. Открыть тот же текст повторно — прежние анализы должны остаться видимыми, включая старые записи этапа 8.
4. Загрузить формат без модели, например PDF: окно «Анализ» должно сообщить, что подходящих моделей пока нет; файл остаётся доступен для скачивания.
5. На тестовом видео проверить прежний просмотр и видеоанализ. Он теперь запускается через общий API, но использует прежнюю обработку YOLO.
6. Проверить разделение профилей: анализ файла одного пользователя не должен быть доступен другому. Для этого нужен отдельный тестовый аккаунт.

## Важные ограничения

- До этого этапа видеоанализ не был полностью проверен пользователем. Мы не можем утверждать, что изменение его вызова проверено на реальном видео без локального теста.
- Смысл классов 0 и 1 у NLP-модели ещё не подтверждён контрольной разметкой. Результат не является диагнозом.
- Нельзя загружать ML-код, pickle или модели через пользовательский интерфейс. Только доверенные разработчики развёртывают адаптеры.
- Путь `/api/models/.../analyze` Python-сервиса — внутренний API. Текущий Docker Compose открывает порт 5010 на хосте: **не публикуйте этот стек в Интернет без закрытия ML-порта, авторизации, проверки входных данных и аудита безопасности**.
- Статус `configured` для видеомодели означает наличие настроенного адаптера, а не подтверждённую успешность реального анализа.
- Изменения проверены статически в среде подготовки. Полная Docker-сборка, настоящий Python ML-инференс и браузерные тесты в этой среде не выполнялись.
