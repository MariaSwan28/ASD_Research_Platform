# Этап 13 — единое понятное представление результатов

## Что изменено

- Одна кнопка анализа для любых материалов в списке и плитках: «Анализировать», «Результат», «Ошибка анализа», «Анализируется…».
- Кнопка открывает общее окно. Открытие истории не вызывает предсказание или запуск старого видеоклассификатора.
- Сначала показаны название модели, дата, понятный вывод и объяснение. Далее — основные показатели с единицами и пояснениями, ограничения, свёрнутые подробности и технические данные.
- Числа отображаются в русской локали с округлением до трёх знаков. Исходная точность сохранена в выгрузке JSON.
- Полный JSON, внутренние коды и метка класса доступны в технических подробностях. Все исходные показатели сохранены.
- Реестр и оба адаптера поддерживают контракт 1.1. Содержимое карточки задаёт адаптер, React не интерпретирует классы по идентификатору модели.
- BFF проверяет обязательные поля до сохранения. Список файлов получает краткий признак существующего анализа с учётом владельца, в том числе старой текстовой истории.
- После перезагрузки страницы кнопка «Результат» сохраняется благодаря данным истории.
- Отдельные кнопки «Смотреть», «Результат», «Анализ / JSON» видео заменены общим действием. Последнее обработанное видео доступно по ссылке у названия материала. Это существующий файл последней обработки, он пока не привязан к конкретному запуску истории.
- Сохранённые результаты 1.0 и прежние текстовые результаты остаются читаемыми. Новая интерпретация им задним числом не приписывается. Для карточки нового формата нужен новый запуск.
- Исправление высоты select из этапа 12.1 включено.

## Обязательные поля JSON результата 1.1

| Поле | Тип / содержание |
|---|---|
| schema_version | Строка `1.1` |
| analysis_id | Идентификатор запуска, назначенный BFF |
| status | `completed` или `failed` — статус выполнения данного адаптера |
| model | id, name, version, modality, operation |
| input | file_id, modality |
| execution | started_at, finished_at, duration_ms |
| conclusion | code, title, explanation — непустые строки |
| metrics | Массив основных скалярных показателей; допустим пустой |
| limitations | Массив строк с ограничениями; допустим пустой |
| raw_output | Полный исходный результат, при ошибке `null` |
| artifacts | Массив описаний файлов; сейчас у двух адаптеров пустой |
| error | `null` либо объект code, message |
| summary | Краткая строка для совместимости с 1.0 |
| parameters | Все исходные показатели в типизированном представлении |
| warnings | Предупреждения прежнего контракта |

Показатель metrics: обязательны `key`, `label`, `type`, `value`, `description`; необязательна `unit`. Тип: string, integer, number, boolean; отсутствие значения — null, а не ноль. Ключи уникальны. Массивы и сложные структуры остаются в parameters/raw_output. Поле artifacts сохраняет прежнюю схему id, label, media_type и необязательный file_id; произвольные URL и пути не принимаются.

`status: completed` означает завершение операции указанного адаптера. Для movement-pose-v1 это извлечение характеристик, а не запуск классификатора. Смысл результата задаётся conclusion.code и объясняется в conclusion.explanation.

Для нового адаптера укажите MODEL.result_schema_version = '1.1' и верните summary, parameters, artifacts, warnings, conclusion, metrics, limitations, raw_output. Общий исполнитель добавит идентификаторы и метаданные запуска. Неполный ответ 1.1 завершается структурированной ошибкой. Адаптеры 1.0 ещё принимаются: для них исполнитель формирует консервативное объяснение из summary без медицинской интерпретации; raw_output содержит прежнее типизированное представление параметров.

## Текст и видео: честная интерпретация

В переданном проекте нет размеченного набора данных или кода обучения, подтверждающего соответствие классов текстовой модели наличию/отсутствию РАС. Поэтому новый главный вывод: «Текст обработан. Значение категории требует проверки». Он объясняет, почему нельзя отвечать по этому результату «РАС есть/нет». Количество распознанных признаков словаря не выдаётся за число признаков РАС. Исходная метка сохранена.

Видеоадаптер показывает «Движения обработаны. Классификация не выполнялась». Длительность, количество кадров, доля кадров с обнаруженной позой, резкие движения и их частота выводятся при наличии значений. Доля обнаружения переводится в проценты только для карточки; исходная величина сохраняется. Качество трекинга не называется вероятностью РАС.

Ошибку загрузки старого видеоклассификатора (scikit-learn 1.3.0 против 1.2.2) этот этап не исправляет. Версия scikit-learn не изменена, чтобы не нарушить ранее проверенную текстовую модель. Также пока не решена отдельная привязка видеоартефактов к каждому запуску.

## Фактически выполненная проверка

- Python: 14 тестов контракта, выполнения адаптеров, HTTP Flask на заглушках и представления результатов — пройдены. Для тестов отдельно установлен Flask; тяжёлые ML-зависимости и настоящие модели не загружались.
- Node.js: 3 теста, включая HTTP + настоящую SQLite, проверку владельца, сохранения JSON, старой истории, признаков в списке файлов и отказов контракта — пройдены.
- React: 10 тестов карточки, выгрузки полного JSON, истории, просмотра без запуска модели, единых кнопок в списке/плитках и смены состояния — пройдены.
- npm run build: успешно, с предупреждениями в существующих App, Login, ChildProfiles, Disk, PopupLink, VideoPlayerModal, sizeFormat.
- Docker и реальный инференс в этой среде не проверялись. Проверки React выполнялись в jsdom, визуальная проверка настоящим браузером не выполнена.
- `npm ci` BFF выявил старое рассогласование package-lock.json с текущим разрешением socks/ip-address. Для проверки зависимости установлены через npm install --package-lock=false. Lock-файл не изменялся; Dockerfile BFF использует npm install, а не npm ci.

## Как применить

1. Сохраните свою текущую папку и данные. Распакуйте архив во временную папку и перенесите изменённые исходники в действующий проект. Не заменяйте свои .env, SQLite, files и dataset данными из другой папки.
2. Из корня действующего проекта выполните:

```powershell
docker compose up -d --build frontend bff ml-service
```

3. Обновите браузер Ctrl+F5. Новая миграция SQLite не требуется.
4. Откройте существующий результат: история и исходные значения должны остаться доступны. Нажмите «Повторить анализ» для получения нового формата 1.1.
5. Проверьте текст и короткое видео; закройте окно, обновите страницу, откройте «Результат». Проверьте историю, подробности и скачивание JSON. Убедитесь, что простое открытие результата не создаёт новый запуск.
6. Проверьте переключение списка/плиток и второй аккаунт. Старые файлы последней видеообработки могут перезаписываться при повторном запуске — изоляция артефактов по запускам остаётся следующим этапом.

Изменены: ml-service/core/result_contract.py, adapter_runner.py, model_registry.py, ml_adapters/parent_story.py, ml_adapters/movement_video.py; bff/services/analysisResultContract.js, controllers/fileController.js; frontend/src/components/disk/fileList/file/{File.jsx,TextAnalysisModal.jsx,AnalysisResultDetails.jsx,file.css,textAnalysis.css,analysisResultDetails.css}; соответствующие тесты. Основной маршрут универсального запуска BFF, структура SQLite, авторизация и профили детей не переписаны.
