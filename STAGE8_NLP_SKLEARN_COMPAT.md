# Этап 8. Исправление загрузки модели рассказов

## Диагноз по Docker-логу пользователя

В контейнере стояла scikit-learn 1.3.0, тогда как MachineNB1.pickle сохранялся под 1.2.2. При загрузке возникал `AttributeError: Can't get attribute '_passthrough_scorer'` на `sklearn.metrics._scorer`. Это внутренний объект GridSearchCV, несовместимый между версиями.

## Изменения

- `ml-service/requirements.txt`: `scikit-learn==1.2.2` вместо `1.3.0`.
- `ml-service/core/text_adapter.py`: при ошибке проверки готовности модели пишется настоящий тип и текст исключения в лог ML-сервиса вместо полностью скрытой причины. Обработчик по-прежнему возвращает безопасный публичный статус `load_or_compatibility_error`; загрузка допускается только для фиксированных проверенных администратором pickle.

## Установка БЕЗ потери пользовательских данных

**Если данные нужны**, лучше обновить в своей существующей папке только два изменённых файла, а не запускать другой проект Compose: скопируйте их из ZIP с сохранением относительных путей. Не заменяйте БД и пользовательские папки. Не используйте `docker compose down -v`.

В папке проекта PowerShell:

```powershell
docker compose up -d --build ml-service
docker compose exec ml-service python -c "import sklearn; print(sklearn.__version__)"
docker compose exec ml-service python -c "from core.text_adapter import text_model_status, analyze_text; print('status:', text_model_status()); print('test:', analyze_text('Ребёнок часто повторяет движения руками и реагирует на звуки.'))"
docker compose logs --tail=100 ml-service
```

Ожидаемая версия — `1.2.2`. Если статус `configured`, список моделей должен показать доступность текстового анализа. Тестовый результат — исключительно техническая проверка, а не клинический вывод.

**Не гарантируется, что одна замена версии решит абсолютно все возможные проблемы**: если сохранённые CountVectorizer и GridSearchCV не были обучены как одна связка, числовой результат может быть некорректен даже при успешной загрузке. Нужны контрольные примеры из бакалаврской версии для валидации качества.

Важно: код и Docker-образы проверены только статически в среде подготовки, фактическая сборка Docker и загрузка pickle в пользовательском контейнере проверяются указанными командами.
